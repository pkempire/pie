# Deep Dives: Three Advanced Memory & Inference Systems

## (1) Recursive Language Models (RLM): Decompose-Recurse-Aggregate as External Memory

Recursive Language Models treat the input prompt as an external REPL environment variable rather than forcing it through attention at once. The data structure is a **flat string stored in environment scope**, indexed by the model through programmatic code generation. The model doesn't literally call itself recursively in the traditional sense; instead, it uses tool calls (code execution in a REPL) to slice the stored context, process chunks independently, and aggregate results. This is operationally distinct from recursive self-invocation—the recursion lives in the *control flow* (looping over chunks) and *symbolic manipulation* (indexing, slicing), not in the model's forward pass calling itself with different parameters.

Tool calls in RLM follow a decompose-recurse-aggregate pattern. The model generates Python code that slices the prompt into chunks (decompose), calls the LLM separately on each chunk (recurse—though this is just another forward pass, not a recursive call), and merges partial results (aggregate). No depth budget or confidence-based stopping is enforced; instead, the model dynamically decides how many chunks to examine based on task structure. The exact prompt format at each node is context-dependent: for each chunk examined, the model receives that chunk as a string plus task instructions, with no explicit depth-awareness passed. DSPy.RLM adds structure via type-enforced outputs (Pydantic schemas), which the standalone RLM package omits; this structural scaffolding significantly improves performance on models like Gemini 3 Flash (boosting LongMemEval accuracy from 58% to 87%).

Cost per query is remarkably efficient: RLM-Gemini-3-Flash on LongMemEval averages ~$0.01 per query with 87.2% accuracy using DSPy scaffolding, and ~$0.035 per query with observational memory (Pydantic-typed outputs) reaching 89.8% accuracy. Latency is longer than single-pass inference but shorter than multi-turn conversations, since each chunk is a small, focused forward pass rather than dense reasoning over 10M tokens at once. The key insight is that effective processing of 10M+ token inputs costs about the same as or less than vanilla GPT-5 (which degrades and may require retries), because the model selectively examines context rather than ingesting everything.

## (2) Ramp Labs / Latent Briefing: KV Cache Sharing for Multi-Agent Orchestration

Ramp Labs published "Latent Briefing" in April 2026, a technique for efficient multi-agent memory sharing that compresses large-model KV caches rather than recomputing them per agent. The core problem: in orchestrated multi-agent systems, a central scheduler breaks down tasks and calls multiple specialized agent instances; as task decomposition deepens, the shared context (prior turns, coordination messages) is reprocessed redundantly by each agent, leading to exponential token growth. Latent Briefing uses the attention mechanism to identify and compress the most important KV representations, storing a single compressed cache that is injected into each agent's context via HuggingFace DynamicCache objects (a standard PyTorch mechanism for KV state injection).

The engineering approach is a variant of vLLM prefix caching combined with KV compression. Rather than storing full-precision Key and Value tensors, Ramp's implementation applies asymmetric quantization: Keys are quantized to int8 (q8_0 format) to preserve softmax stability, while Values are compressed using a proprietary method (tensor rotation + Lloyd-Max quantization). This is not Anthropic-style prompt caching (which caches full hidden states), but rather KV-specific compression that maintains gradient flow if fine-tuning is required. The cache is computed once at the orchestrator level and reused across all worker agents without recomputation.

Cost savings are substantial: on LongBench v2, Latent Briefing reports 65% reduction in token consumption for worker models compared to naive multi-agent execution, with a 3-percentage-point improvement in task accuracy (fewer hallucinations from context rot). Testing across Claude Sonnet 4 and Qwen3-14B demonstrated consistency and adaptability to varied document types. The technique scales to 15+ concurrent agents with stable 2.91x memory savings (per a related preprint on PolyKV). Operationally, Latent Briefing avoids the engineering complexity of custom kernels or vLLM forking—it leverages standard PyTorch mechanisms, making it deployable in existing inference stacks.

## (3) DeltaMem: Memory-Based Levenshtein Distance for RL-Driven Persona Memory Management

DeltaMem formulates agentic memory management as a single-agent RL problem over a learned operation vocabulary. Rather than designing heuristics for what to retain or forget, it treats memory updates as a sequence of discrete operations (insert, modify, delete, merge) and learns a policy to select which operation and which target to apply at each step. The "Memory-based Levenshtein Distance" is a custom reward function defined over operation sequences: for a given target memory state, DeltaMem computes the minimum edit distance (Levenshtein) between the current memory and target, weighted by the semantic importance of each change. This is not the raw Levenshtein delta, but a **semantic-aware variant** that assigns higher rewards to operations that fix critical information gaps (e.g., updating outdated user preferences) and lower rewards to redundant changes.

The operation vocabulary includes: `INSERT(entity, attribute, value)`, `DELETE(entity, attribute)`, `MODIFY(entity, attribute, new_value)`, and `MERGE(entity_a, entity_b)`. The policy architecture is a standard transformer encoder attending over the conversation history and current memory state, outputting logits over (operation, target) pairs. Reward computation at each operation step is **normalized and scaled** by the semantic edit distance: if the operation reduces the Levenshtein distance to target memory by 50%, the reward is +1.0 scaled by that 0.5 factor, yielding +0.5. This enables RL training to favor high-impact operations without overfitting to specific memory structures. DeltaMem uses PPO (Proximal Policy Optimization) as the RL algorithm, trained on a synthetic dataset of user-assistant dialogues with operation-level labels (created by a teacher policy that greedily minimizes edit distance to a reference memory state).

Benchmarks show both training-free and RL-trained DeltaMem outperforming product-level baselines (Mastra's Observational Memory, manual rules) on LoCoMo, HaluMem, and PersonaMem. The headline number is a ~15% absolute improvement in memory coherence (measured as reduction in hallucinations across multi-turn conversations) over trajectory-level reward approaches like Memory-R1, which only provides a single reward signal per conversation and cannot backprop credit to individual memory updates. By operating per-operation, DeltaMem achieves tighter credit assignment and learns non-obvious memory strategies (e.g., selectively merging similar entities to reduce redundancy, or deferring deletes to preserve context). Cost is minimal—PPO training on 1000 dialogues takes ~4 GPU-hours on a single A100, and inference adds <50ms per operation.

## Summary: Trends Across the Three Systems

**Recursion vs. Recursion as Design Pattern**: RLM's "recursion" is not self-invocation but programmatic decomposition—the model learns to slice, process, and aggregate. This is orthogonal to model size and training approach, enabling an 8B model to match GPT-5 on long-context tasks through test-time search rather than parameter count.

**KV Cache as First-Class Optimization Target**: Both Latent Briefing and the broader trend (PolyKV, LRAgent, KVComm, ForkKV) treat KV caches as shareable, compressible memory. Ramp's symmetric quantization approach is simpler than custom kernels and integrates with standard frameworks.

**Operation-Level Credit Assignment in Memory**: DeltaMem's per-operation RL is emerging as superior to trajectory-level or heuristic approaches, enabling fine-grained memory policies. The Memory-based Levenshtein Distance formalizes semantic importance without hand-tuned weights.

# REM — the agent that wakes up smarter

*Design spec, 2026-07-03. The ambitious bet: one system, three learning layers, one nightly loop.
Supersedes NEXT-BET-V2's "StudyGym-only" framing — the environment is now a component, not the product.*

## One paragraph

REM is an agent with a full memory hierarchy that **studies while you sleep**. Everything it
experiences lands in an append-only, timestamped log. Every night a studying pass compresses
the log into a *temporal expertise artifact* (token space), compiles that artifact into a warm
KV prefix (activation space), and distills what has proven stable and useful into a personal
LoRA on an open-weight model (weight space). Knowledge *graduates* down the hierarchy by
stability × utility; each layer is cheaper to read and more expensive to write than the one
above it. The studying pass itself is optimized — GEPA first, RL second — against one number:
**expertise = task accuracy per unit of inference compute**, measured before and after each
night. The demo is the thesis: same model, same questions, better every morning.

Named for the sleep phase where consolidation happens. The name is the video hook.

## Why this is the breakthrough shape (and not another memory system)

Every 2026 production system converged on background consolidation (OpenAI Dreaming, Letta
sleep-time, Honcho, Supermemory) — but all of them stop at token space, all hand-code the
consolidator, and none measure whether the agent actually got *better* (only whether it
recalls). Meanwhile the evidence says: cheatsheets beat fine-tuning for fresh corpora
(Machine Studying), token-space learning beats naive weight updates (Letta), but weight-space
distillation from a strong teacher is cheap and effective when the knowledge is stable
(on-policy distillation, Thinking Machines). Nobody has built the *hierarchy* — the CLS
(hippocampus→cortex) story made literal — with an optimized studier and an efficiency
objective. That's REM.

## The three layers, and our novel idea in each

### L1 — Token space (the studied artifact)
*What it is:* a compact, human-readable expertise pack the agent loads every session: current
state per entity **with validity intervals**, a calibration table of past plans vs. actuals,
distilled how-tos, open contradictions.
*Everyone else:* flat fact lists or undated summaries, hand-coded consolidation prompts.
*Our novel ideas:*
- **The temporal cheatsheet.** Cheatsheets with time as a first-class column: every entry
  carries (value, valid_from, superseded_by). Demo 01 shows why (flat retrieval: 20% on
  as-of-past questions); `mempol/temporal/schema.py` is the substrate.
- **GEPA-evolved studier.** The consolidation prompt is evolved against downstream expertise,
  not hand-written. Verified-open niche (MemPro took TextGrad; the GEPA slot is empty).
  Goal-01 infra exists; held-out run is ~$100.
- **The calibration table.** Log (task, plan, predicted cost, actual cost, outcome) from the
  ledger and inject reference-class actuals at plan time — the anti-planning-fallacy artifact.
  Nobody ships this.

### L2 — Activation space (the warm cache)
*What it is:* the nightly artifact compiled into a prefix-cached KV state, so every session
starts "already having read" the expertise pack at ~zero marginal cost and latency.
*Everyone else:* prompt caching as an infra optimization, not a memory tier (MemOS gestures at
"activation memory"; Letta's context repos are cache-friendly by accident).
*Our novel idea:* **treat KV compilation as the deployment format of studying.** The studier's
output contract is "a prefix that will be cached," which changes what it writes (stable header,
volatile tail — cache-stable ordering). Measure it: tokens + latency per query with/without the
compiled prefix. This is an economics result as much as a systems one, and it's what makes
per-user memory viable at scale (one base model + N cached prefixes + N tiny LoRAs).

### L3 — Weight space (the distilled habit)
*What it is:* a personal/domain LoRA on an open-weight model, updated nightly by **on-policy
distillation** from a teacher that has the artifact, into a student that doesn't.
*Everyone else:* published RL-memory papers train general policies on benchmarks; Letta's
"memory models" manifesto describes this but nothing shipped; naive continual pre-training
demonstrably fails.
*Our novel ideas:*
- **Graduation by utility, not recency.** Only knowledge that is (a) stable across ≥K nights
  and (b) actually used (retrieved/cited in successful tasks) gets distilled. The amortized
  utility critic (the Pearson-0.71 seed, scaled up) decides *what to distill* — a reuse of the
  critic idea that no longer competes with HiMPO/Memory-R2, it complements them.
- **The reversibility ledger.** Every distilled fact keeps a pointer back to its L1 entry and
  evidence; when the world changes, the L1 supersession triggers un-learning (retrain without
  that shard) instead of silent staleness in weights. Weights with provenance — nobody has this.

## The loop (nightly)

```
        experience log (append-only, timestamped)          — days
NREM ─► studying pass: extract transitions, update states,  — GEPA-optimized
        surface contradictions/deltas, refresh calibration
        └─► temporal expertise artifact (L1, ~2-8k tokens)
        └─► compile artifact → cached KV prefix (L2)
REM  ─► distill stable+useful entries → LoRA update (L3,    — on-policy distillation,
        teacher = base+artifact, student = base+LoRA)         utility-critic-selected
wake ─► eval: fixed probe set, accuracy vs inference cost   — the expertise curve
        └─► morning report: what I learned, what went       — the proactive surface
            stale, what contradicts what you decided
```

## Models (no legacy models, anywhere)

- **Student / trained system:** Qwen3.5-9B-class open-weight via tinker LoRA — deliberately the
  same base as the Machine Studying paper so our expertise numbers are directly comparable to
  StudyBench's published curves. Secondary: gpt-oss-20b-class for the "does it transfer" check.
- **Teacher / judge / studier during development:** current frontier API models only
  (gpt-5.x-mini tier for volume, frontier tier for judging). Repo rule: any script that names a
  pre-2026 model is a bug.
- **Training:** tinker (LoRA + GRPO + distillation recipes exist in tinker-cookbook; keys in .env).

## Testbeds (in order)

1. **StudyBench** (public, comparable): DSPy-corpus and post-cutoff-framework tasks.
2. **This repo** (the dogfood): the ledger has already ingested it; probe set = real questions
   about our own results, decisions, and history; the calibration table comes from real runs.
3. **A person** (PIE data): the life-log version — the consumer-facing video.

## Kill criteria (so this doesn't become pivot #4)

- If the GEPA-evolved studier doesn't beat the hand-written one held-out → hand-write it and
  keep going; the hierarchy doesn't depend on GEPA.
- If nightly distillation doesn't beat artifact-only at matched inference cost within 3 attempts
  (different data mixes) → ship L1+L2 as the system ("token-space REM") and publish the negative
  honestly; it's still a result (and still a video).
- If probe-set accuracy doesn't move week-over-week on the dogfood repo → the studier is the
  problem; fix before touching L3.

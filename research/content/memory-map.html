The Shape of Memory

Every AI-memory system answers two questions it never separates: where what-the-agent-knows physically lives, and when it spends compute to organize it. Plot both and the field sorts into three tiers — and the reason almost everyone is stacked in one of them turns out to be the same reason it can't yet learn.

Three tiers, one question

Down the side: where knowledge lives — as re-read text, as a pre-computed KV cache, or trained into weights. Across the top: when you pay to organize it. The color of each tier is what access you need to build there — and that, not taste, is what explains the map's lopsided shape. Hover any system for what it is, why it's placed there, its real bottleneck, and a primary source.

What the shape is telling you. The token tier is packed because it's the only one you can build on a closed API — so every funded company is there, differentiated only by how cleverly they compress text. The cache tier is nearly empty: reusing knowledge as KV activations needs access to the model's internals, so it exists only where people self-host. The weights tier — actually changing the model from experience — needs open weights to train, so it lives almost entirely in research. The field isn't shaped like this by what works best. It's shaped by who's allowed through the door — and the two sparse tiers are exactly where memory stops being retrieval and starts becoming learning.

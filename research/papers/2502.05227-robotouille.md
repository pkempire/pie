# Robotouille: An Asynchronous Planning Benchmark for LLM Agents

## Quick read

Cooking-environment benchmark where the same task families have both synchronous and asynchronous variants. ReAct gpt-4o drops from 47% on sync to 11% on async — a 36pp collapse that quantifies how badly current agent architectures handle parallel waits and interruptions.

## Why it matters to us

Cleanest single-number demo for the contract/checkpoint orchestration system. If contracts let ReAct go from 11% back to 25-30% on async tasks, that's a striking before/after.

## Method in one paragraph

Cooking simulation with multi-step recipes. Sync split: actions execute immediately; async split: actions (like "cook for 10 minutes") return immediately but block the resource until completion. Agent must interleave waiting actions with continued planning.

## Results in numbers

- gpt-4o ReAct sync: **47%**
- gpt-4o ReAct async: **11%**
- 36pp drop is the failure-of-async-handling signature

## What they don't do

- Only ReAct evaluated; other agent architectures (LangGraph, AutoGen, Claude Code) not tested
- Single domain (cooking)
- No middleware tested

## Open questions / followups

- What does each individual failure look like? Are agents missing parallel opportunities, or interleaving incorrectly?
- Could contract-based orchestration close half the gap?

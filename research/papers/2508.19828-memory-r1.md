# Memory-R1: Enhancing LLM Agents to Manage and Utilize Memories via Reinforcement Learning

## Quick read

Memory-R1 frames memory management as a 4-op discrete action space (ADD, UPDATE, DELETE, NOOP) over a flat-text store, trained jointly with the Answer Agent via outcome-driven RL. It's the most directly comparable system to mempol — same approach class (RL-for-memory) on the same benchmarks (LoCoMo, LongMemEval) — but uses trajectory-level reward where we propose per-op.

## Why it matters to us

This is the paper our work has to beat or differentiate from. Specifically: we need to show that per-op outcome attribution gives non-trivial wins over their trajectory-level signal on the same benchmarks. The right ablation pair is "mempol with trajectory-level reward" vs "mempol with per-op counterfactual" — if our contribution is real, the gap shows up there. Memory-R1's K-retention is fixed (not ablated); we should ablate K explicitly and show the contribution is robust to it.

## Method in one paragraph

Two-agent setup: Memory Manager + Answer Agent, both Qwen2.5-7B + LoRA. Manager emits one of {ADD, UPDATE, DELETE, NOOP} per turn against a flat-text store. Answer Agent reads from the store at QA time. Joint training with PPO and GRPO compared. Reward = exact-match on the final answer to a held-out question battery, propagated to every action in the trajectory.

## What they don't do

- No per-op credit assignment — single trajectory reward diffuses across all manager actions.
- No retention-budget (K) ablation; the K is essentially unbounded.
- No comparison to write-time-compression baselines like Mastra-OM.
- No long-horizon (>100 turn) generalization claims.

## Open questions / followups

- What's the trajectory reward variance look like? If it's high, per-op should help significantly.
- What if K is constrained? Does Memory-R1 still win?
- How does it interact with chunking? They likely use the raw-turn substrate which we know underperforms.

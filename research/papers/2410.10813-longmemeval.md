# LongMemEval: Benchmarking Chat Assistants on Long-Term Interactive Memory

## Quick read

The most-used benchmark for "long-term chatbot memory." 500 questions over 30-40 prior sessions per question, ~115k tokens of history. Question categories: info extraction, multi-session reasoning, knowledge updates, temporal reasoning, abstention. Standard target for any memory system claiming "long-term."

## Why it matters to us

Primary eval. The current SOTA published numbers (Mastra 94.87% with gpt-5-mini, OMEGA 95.4% closed, RLM 89.8% with Gemini 3 Flash) set the bar. Importantly: the benchmark allows query-time retrieval, so it doesn't distinguish "memory" from "retrieval over long context." Worth reporting under multiple budget caps to make the comparison honest.

## Method in one paragraph

Static dataset of histories + questions. Each question references content distributed across multiple prior sessions. Evaluation is judge-graded answer accuracy. No restrictions on how the system stores or retrieves the history — full transcript replay is allowed.

## Results in numbers

Judge protocol: GPT-4o, 3-bucket scoring (1.0 fully correct, 0.5 partial, 0.0 wrong). Per-category breakdown is the more informative number than overall.

## What they don't do

- No constraint on retention budget — full-context wins by default.
- Doesn't separate "memory" from "retrieval."
- Personal chat distribution, not project/research workflows.

## Open questions / followups

- What does the LongMemEval-S subset look like? Smaller; useful for cheap iteration.
- Are there held-out questions per session that could be used as Mode D self-supervised signal?
